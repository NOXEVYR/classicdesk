# 自启修复：等待下一次启动，再转为持续自动加载

本修复不把当前会话恢复当作开机成功，也不要求使用者在六小时内重启。

## 已实现的状态转换

1. `Prepare-NextBootHost.ps1` 离线核对已安装版本、保留方案及恢复来源，只替换已固定摘要的宿主。输出是账户专用预备目录，不能发布。
2. `Install-ShellService.ps1 -Action StageHost -ValidateOnly` 只读核对迁移。实际 StageHost 只接受 Stopped/Disabled，在全新受保护目录部署，保留旧安装；不停止正在工作的增强，不启动服务，也不重启。
3. 新宿主支持 `--arm-next-boot`。`Prepare-ColdDiagnostic.ps1 -Action Arm` 默认选择 NextBoot；旧宿主缺少能力时明确拒绝，不悄悄使用限时许可。NextBoot 不能同时指定 ExpiresInMinutes；旧限时检查须显式指定 `-Lifetime Timed`。
4. schema 3 许可的到期字段为零，等待下一次符合条件的启动。旧 schema 2 保留原有到期语义，不升级旧许可。两者均验证同一安装、系统/外壳/宿主/组件/配置指纹、601 秒准备下限、开机计数重置、600 秒启动窗口、外壳尚未出现，并在加载前禁用下一次自动尝试和原子消费。延迟重启不会单独导致 schema 3 过期；系统或配置改变仍拒绝加载。
5. 真实启动和交互确认后，`Complete-ColdDiagnostic.ps1` 绑定同一存活服务、消费许可和证据，写入接受记录并设为持续 Automatic。此阶段不重启服务或电脑。普通后续启动继续使用现有兼容校验和故障保护。

新安装不复制旧 `cold-diagnostic.*`、`service-state.ini` 或接受记录，避免上次过期资料阻塞或误代表本次结果。旧资料保留在旧安装中。schema 3 仍仅允许一次尝试，不是无限重试或未验收的永久兼容授权。管理员可用已有停用入口取消下一次启动。

## 验证边界

策略检查覆盖延迟 1/7/90 天的下次启动、同次开机、时钟倒退、过晚启动、外壳已出现、指纹变化、非法协议以及只消费一次。完成脚本检查旧限时许可与新许可的不同时间规则，继续拒绝服务/启动身份漂移。迁移检查覆盖原布局保持、仅换固定宿主、运行中拒绝、只读校验无设置写入。

候选未安装时，上述源码和隔离检查不构成开机实测。安装需先完成迁移与包核对，再协调管理员确认。随后使用者按正常安排重启；验证导航栏、拖动、顶部点击和当前启动证据，完成持续自动加载配置后才允许升级上传。

当前会话恢复入口继续只管理当前会话，界面明确提示是否禁用自启；限时许可过期单独显示，不能误报为增强崩溃。
