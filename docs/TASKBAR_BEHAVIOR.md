# 任务栏行为与验收记录

2026-09-20 确认的升级要求。后续修改应保留这些规则；应用自身的皮肤不代表 Windows 任务栏已生效。

| 项目 | 确认行为 | 验收 |
| --- | --- | --- |
| 常规尺寸 | 栏高恢复 48 DIP；应用图标 24 DIP，尺寸独立于透明效果 | 150% 缩放下栏高约 72 物理像素，图标约 36 像素 |
| 整体排列 | 开始、搜索靠左，应用单独居中；右侧图标集中排列 | 不因调整栏高而恢复托盘的宽留白 |
| 输入法 | 保留中/英状态和输入法入口，去除多余内边距；内容完整 | 无裁切、重叠或过宽背景框；中英切换均可读 |
| 右边缘 | 时间、日期右对齐，紧邻屏幕最右侧的显示桌面窄点击区 | 时间日期完整；最右侧仍能显示桌面 |
| 桌面 | 前台切到桌面时，任务栏背景透明 | 壁纸连续透过底板；应用仍在后台也不影响 |
| 普通应用窗口 | 非最大化、未铺满的浏览器或应用窗口保持透明 | 即使普通窗口获得焦点，也不出现实心底板；从最大化还原后自动透明 |
| 最大化与全屏 | 当前任务栏所在显示器的前台应用最大化或铺满工作区时不透明，保留浅色/深色配色 | 无边框全屏也能识别；其他显示器上的最大化窗口不触发本屏不透明 |
| 临时浮层与最小化 | 焦点落在任务栏或浮层时检查本屏最上层的可见应用；无法判断时保留状态 | 最小化最后一个窗口或露出普通窗口后自动透明，无需再点桌面 |
| 可读性 | 深色背景配浅色文字，浅色背景配深色文字；应用原图标不改色 | 时间、输入法、网络、音量、电池均可辨认 |
| 资源占用 | 优先窗口事件触发；不做持续截屏、视频帧采样或新增动画轮询 | 分开记录空闲与切换负荷，不宣称零开销 |
| 开机一致性 | 进入桌面时布局已经生效，无需打开 ClassicDesk，不接受登录后脚本再补应用 | 冷启动、注销登录、Explorer 重建均需验证；启动项存在不算通过 |

当前静态透明和紧凑结构已在单屏实机观察到。48 DIP 栏高、24 DIP 图标、44 DIP 应用按钮保持不变。

2026-09-20 实机复测：0.11.6 背景能切换，但深色时托盘文字仍黑；0.11.7 改为整个 XAML 根和托盘根主题后，已截图确认深色背景下时间、网络、音量和电池为浅色，浅色背景仍采用深色文字。输入法的“中”状态图标仍有独立配色行为，不能据此宣称全部图标已完成适配。关闭测试窗口后回到透明。

0.11.8 另补窗口铺满工作区识别和绘制后 750 ms 一次复核。原生策略断言通过；7 项定向宿主/恢复检查、18 项发布边界检查通过。上一轮完整隔离检查 285 项通过，本轮未因纯间距修改重复全部测试。

输入法图片按钮宽度和普通托盘图标边距分别修正。样式组件曾显示 `0x8000FFFF`，要求重启 Explorer 才能激活。

2026-09-20 后续实机验收失败：经用户同意，切换至 0.11.8 并主动重启 Explorer 一次（没有重启 Windows）。新会话中五项布局/菜单组件报告 Loaded，但自适应背景组件报告 Unloaded，诊断属性均未建立。源码存在启动时序缺口：初始化要求任务栏窗口及 Taskbar.View 已存在，过早注入会直接失败。

在 Explorer 就绪后进行同版本组件恢复/重新启用，控制器虽报告增强正在运行，随后系统日志记录 Explorer 的 `0xc0000005` 崩溃并自动重建会话；故障模块为 unknown，尚不能归因于自适应背景组件。同时 StartMenuExperienceHost 报告 `taskbar-start-button-position_1.3.2.dll` 异常。停止重复重载和重启。自动恢复后的背景组件仍为 Unloaded，因此不能宣称动态透明已生效，也不能把控制器 IsRunning 或组件 Loaded 当作视觉验收通过。

0.11.8 新间距尚未完成视觉验收；当前屏幕采集未显示任务栏，未据此推断布局正常。下一步需先修复背景组件的延迟初始化，并隔离排查定位组件及组件卸载/重载期间的崩溃，再进行稳定性和明暗切换验收。保留 48 DIP 栏高、24 DIP 图标、右侧紧凑结构的目标。登录自动接续仍关闭，不能承诺直接重启电脑后自动接续。

2026-09-20 历史实现（此处的需求理解已被用户纠正，当前规则以表格为准）：应用在前台即不透明，桌面在前台才透明。0.11.9 源码按此区分前台类型，普通窗口从自身可见底部取色；取色和窗口深色属性均不可用时仍使用不透明底板。系统全屏应用若主动隐藏任务栏，不强行显示任务栏。已有配置字段 `FollowMaximizedTheme` 保留以兼容恢复记录，设置页改称“应用不透明，桌面透明”。本次在独立目录构建，不覆盖正在使用的 0.11.8，不以规则代码检查代替实机验收；此前组件启动和重载故障仍待修复。

0.11.9 验证：原生策略断言通过；5 项定向宿主检查、83 项前端检查（49 张离屏渲染）、21 项发布边界检查通过。独立运行包 20 项资产的大小和摘要核对通过，旧版清单留存用于恢复。没有启动新版增强、切换桌面入口或重启 Explorer；实机视觉效果尚未验收。

2026-09-20 重启后的续测：确认旧引擎已退出、Explorer 未加载增强模块后，按原事务恢复旧记录，再启用 0.11.9。六项模块均 Loaded，背景诊断建立两个 XAML 根；浏览器前台截图为不透明底板。用户确认点击桌面和切回浏览器能改变透明状态，但最小化后仍需额外点桌面，因此自动切换验收仍未通过。此轮没有重启 Explorer，观察期间没有新的 Explorer/开始菜单崩溃事件；不据此宣称此前加载/热重载缺陷已修复。桌面入口已指向 0.11.9。

用户明确不接受登录后启动引擎再补应用的方式，并确认接受随资源管理器加载的组件，要求任务栏首次出现即生效。曾正常写入的 0.11.9 登录恢复项已通过产品恢复接口关闭，回读 Enabled=false，启动脚本不存在；当前已运行的桌面效果保留。开机一致性必须重新设计并实测，不能将原生设置持久化与动态增强引擎混为一谈，不再默认添加登录脚本或用延迟任务代替。见[外壳加载要求](SHELL_STARTUP.md)。

0.11.10 独立修正最小化切换：不再丢弃已失焦窗口的最小化/隐藏事件；焦点暂留任务栏或隐藏窗口时，以工作区没有可见应用为桌面证据。忽略工具浮窗、最小化、隐藏和被 DWM 隐藏的窗口；可见性检查无法确定时保留原状态。仍无空闲轮询，不增加渐变计时器。原生构建、策略断言、22 项发布边界检查和 20 项资产校验通过；未替换当前 0.11.9，也未声称已解决开机加载架构。

同一开发阶段补早期初始化：在任务栏窗口和 XAML 模块尚未存在时安装事件钩子，待创建/加载后绑定；初始化后复查 DLL 加载竞态。该前置修正不等于已经把引擎部署到外壳启动阶段。独立包放入新的 early-init 目录，保留先前已核对的包与正在运行的 0.11.9。

2026-09-20 用户通过普通窗口截图纠正：只有最大化或全屏铺满才应改变底板。0.11.11 恢复这一判断，普通窗口获得焦点、窗口还原以及最小化露出普通窗口时均透明；前台暂留任务栏时检查最上层可见应用，不要求额外点击桌面。最大化识别限制在任务栏所在屏幕，铺满判断容许 DWM 边缘 2 像素取整误差。保留事件驱动和早期初始化修正，不改尺寸与排列。设置名称改为“最大化或全屏时不透明”，配置字段和历史运行包恢复摘要保持兼容。独立构建不会自动替换实机正在使用的 0.11.9；开机加载要求仍未完成。

0.11.11 验证：原生 DLL 编译及策略断言通过；83 项前端检查（49 张离屏渲染）、23 项发布边界检查、5 项定向宿主检查全部通过；20 项运行资产大小和摘要核对通过。正在运行的 Explorer 与 0.11.9 引擎未重启、未替换；视觉切换和冷启动仍需实机验证。
