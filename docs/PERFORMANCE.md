# 低占用验收

用户要求：优先 Windows 11，替代现有桌面插件，同时不增加整体资源负担。当前尚未获得增强引擎与现有插件的同条件对照数据，不能声称已达标或零占用。

## 实现约束

- 设置前端关闭即退出；不新增自有托盘、定时联网、后台扫描或持续轮询。
- 首次启用由用户操作触发；可选登录恢复只做一次有时限的检查并继续已应用事务，随后退出，不建立常驻监控。皮肤使用本地静态资源，不引入持续播放的动态壁纸。
- 验证窗口关闭后的增强引擎、Explorer 和系统总量；不能仅用前端退出或下载包较小证明轻量。
- 避免同时启用两个增强工具。实机切换前保留旧插件配置，并确保已有恢复路径。
- 若增加的功能导致整体 CPU、私有内存或操作延迟明显变差，先优化或保持为默认关闭的可选项，不直接宣称替代完成。

## 对照方法

同一机器、Windows 构建、显示器、缩放比例和后台程序条件下，各重复三次：现有插件、ClassicDesk 引擎、可选的系统原生基线。分别采集前端打开、前端关闭后静置、连续打开菜单/切换应用三类场景。

记录空闲 CPU、私有内存/工作集及峰值；另测首次启动、应用/恢复耗时、Explorer 稳定性。共享内存不能直接相加当作物理内存净增加；Explorer 本身的数据也不能直接归因于某个插件。

使用一次性只读采样脚本（进程 ID 从当时任务管理器或 Get-Process 获取）：

```powershell
.\scripts\Measure-Resources.ps1 -ProcessIds 1234,5678 -DurationSeconds 30 -OutputPath .\artifacts\resources.json
```

脚本有明确结束时间，不会成为常驻功能，不启动或停止目标程序、不写系统设置；进程退出会标记采样不完整。输出包含进程 ID、名称和启动时间，仅留本机，提交材料使用脱敏汇总。

2026-09-20，在 Windows 11 25H2 单屏、四模块加载、设置前端关闭的状态下，稳定后各采样 30 秒：引擎 CPU 平均 0.0000%，峰值工作集 13.63 MiB、私有内存 2.11 MiB；三个 Explorer 进程 CPU 合计平均 0.0065%，峰值工作集合计 745.43 MiB、私有内存 353.57 MiB。CPU 按整机 16 个逻辑处理器归一化。Explorer 包含 Windows 和其他扩展；这不是 ClassicDesk 的额外内存量。

更早一次采样处于打开窗口和模块初始化阶段，CPU 较高，不能当作稳定空闲值。原生基线未打开相同数量的窗口，且缺少 StartAllBack 同条件数据，因此尚不能断言整体负担没有增加。后续需要同条件三次对照和交互延迟测试。

上游 Windhawk 1.7.3 的便携模式包含新进程检查定时器，增强模块也可能在初始化时获取所需符号。关闭更新检查不等于完全不联网，前端没有轮询也不等于引擎没有轮询。验收必须包含后台引擎和被加载模块的宿主进程。
