# 本地增强试用准备

本地 0.11.6-dev 支持[按需选择四类功能](FEATURE_SELECTION.md)及登录恢复。首次检查仍只选择任务栏；资源管理器与右键菜单可单独勾选，应用范围不会改写用户保存的完整方案。Windows 11 25H2 单屏已观察到开始靠左、应用居中分离和新窗口 Win10 功能区；完整兼容性和同条件性能对照尚未完成。

## 固定组件与离线准备

[资产清单](../runtime/windows-x64-assets.json)记录官方 Windhawk 1.7.3 安装文件、六个上游固定版本模块及一个本地自适应变体的来源、字节数、SHA-256，以及 20 个运行文件。运行文件合计 13,593,050 字节，不包含完整编辑器与编译器。体积不代表常驻内存。

该清单的 SHA-256 为 `A775D708F64B3832F7E23ECC700420DCB5C27C8C8EA3C0EEA3ECE6140AD10BE2`，同时固定在前端代码中。六个原模块来自官方预编译下载；自适应变体由本项目源码构建。记录上游源码修订不等于已完成上游二进制的独立重编译一致性验证。第三方二进制不提交到源码仓库，也不加入当前公开前端包。

下载清单中的官方安装器和模块，校验其摘要。使用已安装的 7-Zip 解压安装器，**不执行安装器**。保留解压后的 `Engine/$R1` 目录结构；不要用 PowerShell 双引号展开 `$R1`。将六个上游模块按清单中的 `sourcePath` 命名后存入同一目录，再按 [原生构建说明](../native/README.md) 构建自适应变体并放入该目录。准备脚本不会下载文件、安装服务或启动引擎。

```powershell
dotnet publish ./src/ClassicDesk/ClassicDesk.csproj -c Release -o ./artifacts/local-test/app
./scripts/Prepare-Runtime.ps1 `
  -ApplicationDll ./artifacts/local-test/app/ClassicDesk.dll `
  -Installer ./artifacts/downloads/windhawk_setup.exe `
  -ExtractedInstaller ./artifacts/downloads/extracted `
  -ModuleDirectory ./artifacts/downloads/modules `
  -Destination "$PWD/artifacts/local-test/原生组件-未启用"
```

父目录必须已存在，目标目录必须不存在。脚本逐项验证后生成停用配置，将所需运行库从 `.dll` 映射为模块实际导入的 `.whl` 文件名，最后通过产品内置摘要检查。失败时保留新建的局部目录，不覆盖重试，也不清理已有资料。生成的所有权标记、配置和以后产生的恢复记录仅留本机。

## 检查与试用

只读命令通过 `dotnet` 调用，便于接收 JSON 输出；不会打开设置窗口、创建恢复记录或启用增强：

```powershell
dotnet ./artifacts/local-test/app/ClassicDesk.dll --check-runtime "$PWD/artifacts/local-test/原生组件-未启用"
dotnet ./artifacts/local-test/app/ClassicDesk.dll --inspect-system
```

准备后基础四个模块均为 `Disabled=1`，主程序和引擎均为 `SafeMode=1`；更新检查、托盘和工具窗口保持停用。要实际试用，打开此构建的设置窗口，进入“系统应用检查”，选择功能并重新检查，核对提示后点击“试用所选功能”。首次启用仍需要显式操作，打开设置窗口不会自动应用方案。

## 透明任务栏与紧凑托盘

任务栏高级选项新增两个独立开关：透明任务栏移除底板颜色和模糊，保留图标、文字与蓝色运行指示条；紧凑托盘减少右侧留白，不缩小应用图标，时间右对齐并紧邻屏幕右端的显示桌面点击区。这两项使用可选的 Windows 11 Taskbar Styler 1.9；透明效果额外使用 Taskbar Background Helper 1.2 控制原生合成背景。后者使用 color 模式和透明色（alpha=0），onlyWhenMaximized=0，不创建窗口状态监控线程。修改范围为任务栏控件和原生背景；没有增加独立常驻前端或动画计时器。模块仍有资源开销，不能宣称零开销。

当前属于本地试验功能。Windows 11 25H2（26200.9457）单屏、150% 缩放下，已观察到背景透出壁纸、微信托盘图标完整显示。托盘使用内容自适应宽度并减少内层留白，避免把外框硬压窄后裁切图标。此前实机会话曾出现样式与模块均加载、任务栏仍显示不透明白底的情况；半透明效果必须在桌面壁纸背景下另行验收，不能以“增强正在运行”代替视觉验收。多显示器、其他缩放和重登后效果仍待核对。

新运行包包含样式 DLL，缺省配置不启用它；按勾选生成样式配置，并把样式和原生背景分别作为第八、第九个目标保存原始状态、应用、接续和恢复。旧七目标记录、[八目标样式试用记录对应清单](../runtime/windows-x64-assets-styler.json)和[旧资产清单](../runtime/windows-x64-assets-legacy.json)仍可恢复，不能将新清单覆盖到正在运行的旧目录。内置样式只接受固定组合，不开放任意 XAML 输入。

## 最大化窗口明暗跟随（0.11.6 本地开发版）

“跟随最大化窗口明暗”会启用透明任务栏：桌面透明，前台最大化窗口按底部可见内容明暗选择浅/深底板，并调整任务栏文字主题。关闭透明会同时关闭跟随。输入法内层留白继续收紧，正常栏高采用 48 DIP，图标仍为 24 DIP；时间右对齐和显示桌面窄区保留。

该模式用本地构建的 `taskbar-background-helper_1.2-classicdesk.1.dll` 替换同一个第九目标中的静态背景模块，不再增加模块槽位或独立常驻进程。工作线程等待窗口事件，180 ms 单次延迟合并事件；九点亮度采样不保存图像或页面内容。没有持续采样，但事件和线程仍有少量资源开销。多屏、所有应用内无事件的颜色变化不在当前支持承诺内。源码、许可证、构建依赖与边界见 [native/README.md](../native/README.md)。

新运行时校验 20 个资产，保留静态背景 DLL 供关闭跟随时回退；旧静态 19 资产清单保存于 [windows-x64-assets-static.json](../runtime/windows-x64-assets-static.json)，兼容恢复旧事务。不得覆盖活跃旧运行目录的清单或 DLL。实机验收状态以 [TASKBAR_BEHAVIOR.md](TASKBAR_BEHAVIOR.md) 为准。

## 登录后继续已有增强

增强正在运行时，可勾选“登录后保持上次已应用的增强”。这会添加当前用户启动目录中的 `ClassicDesk-resume.vbs`，以隐藏方式调用 `--resume-login`；不会创建服务、计划任务或常驻监控程序。前端不打开窗口，等待 Explorer 稳定后只检查一次，结束即退出。启动目录被 Windows 或其他管理工具禁用时不会运行；不能把启动项存在当作下次登录已验证。

登录恢复仅接续唯一的 Active 事务：核对固定组件、原引擎身份、冲突、整套已应用配置，再启动引擎并保存新的进程身份。不会重新应用草稿、改写已记录设置、丢弃原始备份，或启动第二个已有引擎。配置被外部修改、身份不明、启动结果未知时保留记录并停止，可在面板查看上次检查结果。

0.11.3 修复了注册表修订误判：Windows 记录的是整个 Advanced 键的更新时间，不是 TaskbarAl 单值的更新时间。接续或恢复事务时，对这一项核对是否存在及实际 DWORD 值；文件配置仍核对完整字节和修订。启动、写入的最后提交仍冻结并检查当前修订，不覆盖确认后的变化。原始回执保持不变。已运行的引擎也要通过整套规则校验，不能只凭进程存在显示成功。登录检查去掉固定 15 秒等待，检测到 Explorer 连续稳定后即继续运行，等待仍有明确上限。

关闭勾选只关闭以后的登录恢复，当前增强仍运行。“恢复原设置”先关闭登录恢复，再恢复本事务拥有的设置。引擎已退出但配置仍保留时，面板显示“继续运行”。移动安装目录前需从原目录关闭登录恢复；不接管另一份安装的启动项。

启动恢复已通过隔离测试；下次真实 Windows 登录的自动执行仍待观察。资源管理器模块对新建窗口生效，已打开的窗口可能保持旧布局，不应为了切换外观反复重启 Explorer。

若检测到 StartAllBack 已加载或其他 Windhawk 实例，启用被阻止。应先保存工作，再通过现有工具停用并确认其卸载出当前会话；必要的注销或 Explorer 重启属于单独的实机切换步骤，准备脚本不执行这些动作。恢复使用原运行目录和本机事务记录，不能删除目录后指望恢复仍可执行。

现场观察中，StartAllBack 3.9.25 在 Windows 11 25H2 上勾选“为当前用户禁用该程序”后，单独重启 Explorer 仍有完整组件加载；之后用户重启电脑，再次检查仍检测到加载和经典任务栏。停用勾选或重启不能当作组件已退出的证据。遇到这种情况继续保持冲突阻断，不自动注销、反复要求重启或仅凭注册表停用值忽略已加载模块。

首轮需核对开始靠左、应用居中、尺寸变化、开始与搜索窗口、多显示器/DPI、恢复，以及[整体资源对照](PERFORMANCE.md)。配置和进程回读成功不等于视觉效果验证通过。上游便携引擎会驻留并定时检查新进程；关闭前端后不能声称整个方案零轮询或零占用。
