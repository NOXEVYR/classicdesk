# 开机方案更新

0.11.15 设置前端支持管理已安装的 ClassicDesk 开机服务，沿用 0.11.14 原生组件。此入口不会替尚未安装服务的电脑安装组件；公开 0.10.0-preview 下载包保持原样。

## 使用步骤

1. 在设置页选择或编辑布局，点击“系统应用检查”。已安装服务时会打开“开机方案”窗口。
2. 对比“已保存的开机方案”和“本次更新方案”。任务栏布局与尺寸、紧凑托盘、透明规则、资源管理器样式、右键菜单均属于本次完整方案；界面皮肤只影响 ClassicDesk。
3. 点击“更新开机方案”，完成 Windows 管理员授权。成功后显示“等待重启”。当前桌面继续使用原规则，程序不会主动重启 Windows、Explorer 或服务。
4. 自行保存工作并重启，新规则随开机组件加载，设置窗口不需要启动。重启前再次更新会替换下次启动方案，旧安装仍保留。

“保存方案”只保存编辑草稿；“更新开机方案”才更新服务的下次启动配置。方案相同、安装检查失败或操作尚未完成时，更新按钮不会重复提交。Windows 原生任务栏对齐需要保持居中；若被外部改动，检查会提示，应用不会顺带覆盖该注册表设置。

## 停用与恢复记录

窗口中的“停用下次开机增强”仅取消自动启动，当前桌面保持原状。程序目录同时提供 `Disable-ClassicDesk-NextBoot.vbs`：即使模块配置检查失败，也可独立请求管理员停用当前归属明确的服务，不依赖某个旧安装目录。它不会删除安装、恢复记录或强制结束外壳进程。取消管理员授权会保留原配置。

原始便携恢复依据保留在回执 `Source` 中，新方案单独保存在 `TargetProfile`，上一安装位置保存在 `PreviousInstallation`。不要把停用开机组件理解为清除所有历史 Windows 设置；本阶段没有新增系统对齐值恢复或已停用服务的重新启用界面。

## 验证范围

方案编译使用既有的受限参数映射。新暂存目录只包含既有资产及重新编译的模块 INI；写入前后检查哈希、进程范围、账户和服务归属。管理员安装器只改变 SCM 下次启动路径，不启动另一个引擎。

覆盖四个预设、关闭各类增强、过期回执、改动代码、注入范围变化、重复操作、管理员授权取消、模拟 SCM 暂存与 `WhatIf`。界面在常规和最小尺寸离屏检查；真实安装完成只读检查。不同方案的真实管理员写入与重启结果仍待实测，不能用模拟安装器结果替代。

没有新增常驻进程、定时器或网络检查。准备与校验仅在操作时进行，会产生短时文件读取和独立版本目录；不宣称整体占用为零。

开发检查：

```powershell
# 使用本地已核对的组件预备包；包含账户和方案的准备目录不可公开上传。
.\scripts\Test.ps1 -ServiceBundle '<本地已核对的 service-package.json 所在目录>'
# 只读核对当前安装及开机方案，不打开窗口或写入系统设置。
ClassicDesk.exe --inspect-service-layout
```
