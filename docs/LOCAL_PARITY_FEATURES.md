## 可独立使用的 ClassicStart

从设置标题栏“布局与开始菜单”进入工作区，点击“打开独立开始菜单”；或者显式运行 `app/ClassicDesk.exe --classic-start`。菜单正常打开前不会扫描程序，默认展示不能启动的演示列表。点击“刷新本机应用”只读扫描当前用户与公共开始菜单中的 Programs 目录，读取快捷方式文件名与子目录分类；不解析快捷方式内容、不查询真实窗口标题、不自动打开程序。

支持搜索程序名称和分类（中文、全角及大小写）、所有程序/分类、固定与取消固定、固定列表顺序、右侧八种常用位置、自定义本地文件夹、列表/磁贴/紧凑样式、16/24/32 px 程序图标、固定显示数量、正反排序、入口图标和用户目录标题显示。Enter 或明确点击才请求启动，双击必须来自具体结果项；列表空白、固定按钮、滚动条和演示结果不能启动。Ctrl+F、上下键、Escape 配合搜索和选项操作。

启动前重新核对本快照中的 ID、允许目录、存在性、快捷方式类型及路径重解析点。快捷方式自身指向的程序/网页由 Windows 处理；ClassicStart 不声称审计其目标，也无法提供从路径检查到 Windows 打开之间的原子文件系统保护。

只有“保存设置”写入独立 `LocalAppData/ClassicDesk/classic-start.json`，保留原字节备份和期望修订；损坏、未知/重复参数、过大文件、外部变化、网络/设备路径拒绝覆盖。固定、样式及目录编辑均先作为草稿，导入不自动保存，导出要求新文件。未保存时关闭有放弃确认，取消保留草稿，不自动保存。

这是独立程序菜单，未接管 Windows 开始按钮或 Win 键；尚缺商店应用完整枚举、原生应用图标、跳转列表、完整右侧链接/子菜单、XP 弹出菜单、最近/常用历史及电源动作。不会后台采集使用历史。

## 任务栏与托盘设计

工作区新增四边停靠、四种合并/标签策略、三档开始/应用位置、图标与栏厚、80–240 px 标签按钮宽度、两端边距、分段背景、0–16 px 托盘间距与 17 个系统图标入口。六个合成窗口按应用身份合并，“占满时合并”根据模拟屏幕宽度和可用区域决定；不够显示时报告溢出数量。纵向缩略隐藏文字，同时保留标签设计值。托盘显示项目不表示设备存在或权限已经改变。

这些选项目前完整覆盖编辑、保存、导入导出、按页重置、撤销、预览计算与离屏渲染；**未接入真实任务栏增强模块**。存储单独使用 `LocalAppData/ClassicDesk/TaskbarDesign.json`，不传给现有 ShellProfile、组件计划或系统应用事务，保存不会让现有引擎执行新的设计。原工具第五个“从不合并”档位差异待实测，不伪装为另一个已完成档位。

已有的任务栏尺寸、开始位置、功能区和右键菜单增强链路继续保持，但本轮没有启用它们。资源管理器其他差距、托盘浮层风格、多屏和系统恢复等项目仍见 STARTALLBACK_PARITY.md。

## 验证与边界

多轮验证覆盖独立功能、损坏/外改/路径替换、异步返回与关闭、草稿确认、键盘、不同窗口尺寸及 100/125/150/200% 离屏输出。完整旧回归和最终 ZIP 提取验证单独记录在 VALIDATION.md 与交付摘要。离屏 DPI 输出不等于跨真实显示器验证；注入启动回调不等于真实应用已启动；合成程序文件不能替代实际安装的所有类型应用。

开发和发布检查没有显示实机窗口、写Windows设置、设置任务栏自动隐藏、停用StartAllBack、安装服务、启动增强引擎或注册全局键盘绑定。本地前端替换与这些系统行为分开；完整替代仍待增强后端和获准的实机验证。
