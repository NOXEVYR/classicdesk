# 旧组件退出后的版本切换

0.11.12-dev 增加显式命令行切换入口，替代此前放在开发产物目录中的一次性切换脚本。此流程不是开机加载器，不建立启动项，也不承诺任务栏首次显示时生效。

## 准备与执行

在新版程序目录中，由操作者显式调用（路径均为绝对路径）：

```powershell
ClassicDesk.exe --prepare-cold-upgrade <旧组件目录> <新组件目录> <新的切换记录.json>
ClassicDesk.exe --apply-cold-upgrade <切换记录.json>
```

准备阶段核对新旧运行包及旧恢复记录，保存原来已经应用的方案；不会采用未应用的编辑草稿。切换记录必须新建，不能覆盖同名文件。记录包含本机路径和方案，必须保留在本地，不纳入公开包或仓库。

执行时必须确认旧引擎已退出，而且 Explorer、开始菜单进程未加载增强组件。任何进程或模块身份不确定都拒绝切换；不会主动关闭引擎、重启 Explorer 或注销 Windows。即使检查后出现竞争实例，底层宿主也拒绝执行停止进程的请求。

通过检查后，先调用旧事务的恢复流程，再按旧方案启用新版。恢复失败时不启用新版；新启动失败或结果未知时保留恢复记录，不自动重试或重启旧版。新版启用后的状态仍为 `activated-unverified`，不能据此宣称视觉验收通过。

旧登录恢复入口必须已经关闭。此流程不创建替代登录脚本，不设置服务，不修改桌面快捷方式，也不改变设置窗口中保存的草稿。启用成功后的设置入口需由安装切换流程指向对应新版。

## 验证与限制

- 20 项隔离专项检查覆盖进程仍在运行、模块仍在加载、记录/方案/二进制变化、恢复失败、启动结果未知，以及方案完整传递。
- 现有 86 项事务检查和 23 项发布边界检查通过。
- 本机已用生产入口生成新版切换记录，确认旧引擎仍在运行，48 DIP 栏高与 24 DIP 图标等已应用参数保持完整。未执行实际切换。
- 主机检查与文件检查不是针对恶意并发写入者的原子系统事务；现有事务归属和逐步回读仍负责拒绝冲突。
- [资源管理器启动阶段加载](SHELL_STARTUP.md)仍需独立实现与实机验收，当前不能要求用户“直接重启就生效”。
