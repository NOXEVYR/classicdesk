# 开机兼容保护与任务栏诊断（本地补丁）

本地 `startupguard` 分支针对系统外壳更新后仍自动注入旧组合、以及仅凭服务状态判断桌面成功的问题增加保护。公开预览版下载仍指向原发行。故障定位、Explorer 生命周期与完整功能补齐的当前顺序见 [重构计划](REBUILD_PLAN.md)。

## 启动边界

服务在加载引擎前计算当前 Windows build/UBR、外壳文件、宿主、组件清单和实际方案 INI 的 SHA-256 组合指纹。受保护目录内的 `shell-compatibility.ini` 必须包含 Schema=1、EnhancedShellAccepted=1 和完全匹配的 Fingerprint。缺少验收、环境变化或读取失败时，服务记录具体原因并尝试停用后续自动启动，不加载引擎；停用失败也会记录错误。

本补丁不会自动生成验收凭据。原生任务栏正常、服务可启动或只读检查通过，都不能代替增强加载后的实际验收。候选提供[单次冷启动试验](COLD_DIAGNOSTIC.md)与[显式验收完成入口](COLD_DIAGNOSTIC_COMPLETION.md)：先进行真实增强冷启动与交互验证，绑定同次开机及证据后才恢复常规自动加载。这两条路径仍需实际安装验收；改变系统外壳文件或方案后需重新验收。

开机方案可在服务已停止且禁用时准备；升级只修改服务下次启动路径，保留 Disabled。重新启用自动启动时仍须核对来源、文件摘要与原生兼容结果。旧版本目录和恢复记录保留。

## 当前会话恢复

本地分支提供“本次启用已保存方案”和 `--start-shell-session` 入口。安装助手核对受保护组件、当前 Explorer PID/会话/创建时间及系统/方案指纹，临时启动服务；宿主在加载引擎前先确保下次启动为 Disabled，绑定的 Explorer 退出后结束该次运行。它不生成兼容验收凭据，不开启正式开机增强。

此入口仅允许已有桌面的受控试运行，不能替代冷启动。资源管理器布局等在窗口创建时生效的能力仍需独立生命周期检查；当前文件窗口发生异常时，服务运行与 DLL 已加载不代表效果/交互成功。

## 只读诊断

设置页的“检查当前任务栏”检查当前登录会话的任务栏窗口、子窗口结构、WM_NULL 有界响应、主外壳 PID/会话匹配和 ClassicDesk/Windhawk 模块来源。坐标注明物理像素及 DPI，读取失败保留为未知。它不发送点击、不改 Windows 设置、不启动引擎，也不验证屏幕像素或真实点击。

```powershell
& .\app\ClassicDesk.exe --inspect-taskbar-health
& '<受保护安装目录>\ClassicDeskShell.exe' --inspect-compatibility
```

兼容查询退出码 0 表示查询成功；只有 JSON 的 `state` 等于 `compatible` 才表示凭据匹配。诊断报告 `Healthy` 仅表示报告中列出的结构和响应检查通过。

## 验证范围

原生决策与指纹测试覆盖缺少/无效凭据、环境变化、文件丢失/锁定、额外方案文件。安装隔离测试覆盖禁用状态下更新、拒绝未验收启用，以及有效兼容结果仍须通过来源检查。任务栏诊断使用合成观察验证未知状态、窗口身份变化和模块来源识别；真实机器只运行只读采集。

隔离回归入口为 `scripts/Test.ps1`。完整开机、增强模块实际加载、鼠标/中文输入和睡眠唤醒仍须另行实机验收。此保护不证明任何单个增强模块或 Windows 更新是任务栏缺失的根因。
